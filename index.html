Whole-body humanoid navigation
Updated Oct 18 · Agent-aided distillation

01 / Research question

Risk-conditioned navigation

Generate motion references offline. Train a student that acts in closed loop from perception.

Hypothesis: agent-generated alternatives let one policy reach the same goal with different routes, skills, and contacts.

Research proposal. RL = reinforcement learning. Distillation trains a student to imitate a teacher. Based on the project research plan.

02 / Task and command

One goal pose. One risk preference.

Goal g = (x, y, z, yaw)

Target robot-base position and yaw in the world frame. The same command applies to every skill.

Risk preference β

Controls how strongly poor outcomes affect decisions. Supplied to the student at deployment.

Navigation outcome

Reach the pose and stabilize before timeout. Record falls and unintended collisions; planned hand support is allowed.

β is a preference, not a promised failure probability. A budget δ would require explicit failure constraints and separate validation.

SE(2) specifies planar position and yaw; z adds height relative to the world origin. Perception and robot state are observations.

03 / Interactive example

Same start and goal. Different behavior.

A risk metric compares outcome distributions, rather than assigning a fixed risk label to each skill.

10%: more conservative → 100%: mean return

CVaR means conditional value at risk: here, the average of the worst β fraction of returns. Select the highest score. β = 10% does not mean a 10% failure limit.

04 / Stage 1: motion tracking

Train one tracker across motion references.

Reference input

An ordered sequence of poses, velocities, and contacts. Train across clips, valid entry frames, and transition motions.

Feedback control

The tracker receives the current robot state and upcoming reference frames, then outputs joint commands. Freeze it for initial student training.

A reference specifies desired motion. The tracking policy corrects errors while executing it.

Proposed shared multi-motion RL tracker. A predefined repertoire is a useful starting assumption; synthesis cannot create an unsupported physical capability.

05 / Offline synthesis

The agent proposes alternative trajectories.

Choose route, clip, entry frame, exit frame, and scene placement → stitch → test in simulation → revise.

This graph illustrates reference construction. The proposed deployed student does not use a GNN or graph search. Agent decisions are evaluated by executing the reference with the tracker.

06 / Stitching: PHP precedent

Match the entry. Smooth the switch.

Motion matching

Search annotated entry windows using foot state, root velocity, and the desired future root path.

Inertialization

Apply the current-to-target motion offset at the switch, then decay it with a damped spring. Play the main maneuver through its annotated end.

PHP: motion synthesis and inertialization. Smooth references still need physical validation with the tracker; arbitrary cuts during flight are excluded.

07 / Which reference trains the student?

Select a reference for the task and risk.

Build the library

Store scene, valid starting states, goal, reference timing, and outcomes across randomized executions. Keep failure counts.

Select a training example

Sample scene + start + goal + β. Rank compatible references by the risk metric. Use a consistent tie-break when routes are equally good.

Generate multiple alternatives for the same task. Otherwise the student can associate behavior with the scene and ignore β.

If no reference is executable from the sampled start, regenerate or resample. Teacher outcome estimates guide supervision; they do not establish the student’s risk.

08 / Stage 2: closed-loop distillation

Query the teacher at the student’s state.

Teacher: current student state + selected reference → corrective action target.

Student: observation history + goal + β → action executed in simulation.

Compare student and teacher actions at the same state. Update the student while it controls its own rollout.

DAgger means dataset aggregation: collect teacher labels on states visited by the student. The teacher is a feedback tracker, not an autonomous route planner.

09 / Timing and supervision validity

Preserve timing and gate supervision.

Track a continuous phase

Initially advance with the validated reference timing. Different approach speeds use different references; do not rematch to an arbitrary frame every step.

Gate teacher supervision

Use imitation only where the tracker can provide useful corrections. Outside that range, use navigation RL and collect failure cases for synthesis.

Changing references requires a reachable, contact-compatible transition. Recovery is a capability to train and validate.

PHP masks imitation outside its original tracking-validity threshold while retaining RL: Appendix B.3. The phase and recovery rules above are our proposed starting design.

10 / Distributional PPO

Risk conditioning changes policy updates.

Critic: predicts future navigation returns under the current student and β. Failures must affect those returns.

Actor: receives β. An advantage estimates whether an action improves on the policy’s usual outcome.

A return distribution alone does not change behavior. The risk metric must influence the policy update.

Distributional proximal policy optimization (DPPO): Schneider et al., Learning Risk-Aware Quadrupedal Locomotion. They use risk-adjusted value estimates in PPO and condition the actor on risk. Our extension adds goal navigation and agent-generated teacher references.

11 / One command, three training roles

Make risk conditioning consistent.

Simple architecture first

Concatenate β with perception and robot-state features. A special visual encoder is optional; meaningful supervision is essential.

Allow useful deviations

Train for goal completion, time, and failures. Reduce imitation as needed so a successful alternative or recovery is not penalized merely for differing from the reference.

Use the same risk metric for reference ranking and RL. Evaluate the student’s own outcomes. A first experiment holds β fixed per attempt; mid-maneuver command changes need separate training and validation.

12 / Evaluation

Risk conditioning produces different motion.

MeasureEvaluate on unseen obstacle arrangements
NavigationGoal completion, timeouts, route length, and completion time.
Risk responseFalls, unintended collisions, and lower-tail returns across β; report uncertainty intervals.
Behavior changeRoutes, approach speeds, contact choices, and recovery after disturbances.

A conservative policy should use an available safer route. Stopping is not goal completion.

Hypothesis to test, not a demonstrated result. Evaluate full attempts, repeated trials, and multiple training seeds. Check both risk response and navigation competence.

13 / Related work and scope

Test the value of agent-generated data.

PHP

Borrow motion matching, transition smoothing, and teacher supervision during student rollouts.

Risk-aware DPPO

Borrow a distributional critic and risk-conditioned actor. Adapt the objective from velocity commands to goal navigation.

Agent-aided synthesis

Propose routes, entry frames, and transitions; evaluate them in simulation; expand training coverage using student failures.

Research question: does the agent improve coverage and risk-controllable navigation at the same simulation budget?

Broader scene coverage is a hypothesis. Generalization remains limited by the motion repertoire, teacher recovery ability, and what the student can observe.

14 / First experiments

Separate data quality from risk learning.

Test the agent’s contribution

Compare fixed synthesis, random search, and agent-guided synthesis. Match motion libraries and simulation budgets.

Test the learning objective

Compare risk-conditioned imitation, imitation + PPO, and imitation + DPPO. Keep reference coverage and observations comparable.

Start with rigid obstacles and tasks with alternative routes. Expand to compound scenes using failures from the trained student.

Local starting points: motion tracking and perceptive locomotion. At deployment, no reference library, teacher, or graph planner is required. Longer routes may require map or memory inputs.
