01 / Research question

Risk-conditioned
navigation

Reach the same goal with different routes, skills, and contacts.

Whole-body navigation from A to B, using perception and a predefined library of skills.

PROPOSED HYPOTHESIS

A risk budget controls how the robot reaches its goal.

At deployment: observation history + goal pose (x, y, z, yaw) + risk budget. The same command applies to every behavior.

Proposal, not an experimental result. Based on the project research plan.

02 / Task formulation

Navigate from A to a target pose B.

One navigation command for all skills: SE(2) + z, written as g = (x, y, z, yaw).

Command

Target robot-base position (x, y, z) and yaw in the world frame.

Success

Reach the pose within tolerance and stabilize before timeout.

Failure

A fall or unintended collision. Planned hand support is allowed.

Risk budget δ = maximum permitted failure probability for the complete navigation attempt.

SE(2) specifies planar position and yaw; z adds height above the world-frame origin. Perception and robot state are observations. Risk budget δ is a separate preference. Formulation: risk-constrained planning.

03 / Controllable behavior

Same start and goal. Different behavior.

Select the fastest candidate sequence whose estimated failure probability fits the budget.

0%–10% permitted failure probability

Hand support: 9 s, estimated failure probability 3%.

Risk depends on the robot state and scene. Hand support is not always safer. If no candidate meets the budget, replan or report the goal as infeasible.

04 / Skill-library assumption

Start with predefined, reusable skills.

Given: a motion repertoire

Train one shared multi-motion tracker. Measure which states and terrains it can handle.

Learn next: graph planning

Freeze the tracker while learning transition predictions for graph search. Optionally fine-tune the tracker afterward.

Fixed skill categories do not require frozen controllers. Keep a frozen-library baseline to measure the value of adaptation.

A skill includes a feedback controller and conditions for starting and ending. A missing capability requires a detour or a new skill. Foundation: Sutton, Precup & Singh: options.

05 / Graph search at inference

Search the skill graph to reach the goal.

At inference, update feasible edges from perception and search for a route to g under risk budget δ.

Execute the next skill, observe its outcome, and replan at valid transition points. Edge predictions depend on robot state and scene; validate whole-sequence risk.

06 / Transition example

The next obstacle changes the jump.

Command a goal pose beyond the beam. The policy chooses how to cross the gap and crouch beneath the beam.

Evaluate the full sequence: a successful jump can still leave the robot unable to crouch in time.

07 / Skill training

One pose command. Learned skill transitions.

Entry-state training: start crouching from actual jump outcomes.

Terminal-state training: train jumping to finish in states crouching can handle.

Landing velocity, posture, and contacts are learned execution choices; they are not additional user commands.

Optional: fine-tune tracker transitions with planner parameters frozen. Re-measure risk. Related: terminal-state regularization—training one skill’s final state to suit the next skill.

08 / Offline discovery

The agent proposes. Simulation evaluates.

An offline language-model agent proposes skill sequences; simulation measures their outcomes.

Output: a skill-transition library and execution data

Store references, starting conditions, final states, time, and failures. Execute candidates with the frozen tracker to train graph predictions.

Test the agent’s value against random search and uncertainty-based sampling, which selects trials where the learned model is least certain. Use equal simulation budgets.

09 / Proposed training and inference

Two stages. Explicit graph search.

Learn: scene- and state-dependent edge feasibility, failure probability, time, and final states from execution data.

Search: use those predictions to choose a route toward g under δ. A graph neural network (GNN) is one model option.

Freeze the tracker while learning the planner. Optional tracker fine-tuning keeps planner parameters fixed.

No teacher–student stage is required. A frozen planner still updates its graph and replans. After tracker changes, revalidate its edge predictions and whole-route risk; reject or recalibrate stale predictions.

10 / Related work

Combine established methods; test the integration.

Our proposal: learn graph predictions, then explicitly search for skill sequences during navigation.

PHP combines motion synthesis and teacher–student training. We borrow the idea of diverse transitions; our proposed tracker-and-planner training retains graph search at inference. Novelty requires further review and experiments.

11 / Evaluation

Risk conditioning produces different motion.

Fixed-route courses

Require the same crossings. Measure skill and contact choices.

Multiple-route courses

Allow detours. Hold goal pose g fixed and vary risk budget δ.

12 / First implementation

Train the tracker, then the graph planner.

01 / TRAIN TRACKER

Multi-motion tracking

Train one motion-conditioned policy with reinforcement learning. Validate skills and transition references, then freeze its parameters.

02 / TRAIN PLANNER

Perceptive graph planner

Learn transition feasibility, time, and resulting states from tracker rollouts. Search the graph using g and δ; test navigation success.

OPTIONAL / FINE-TUNE

Adapt the tracker

Freeze planner parameters and improve tracking under its selected sequences. Retest graph predictions and risk before deployment.

Perception requirement: represent both the floor and the underside of the beam. A single elevation map cannot describe both at the same horizontal position.

Current starting points: motion tracking and perceptive locomotion. Validate the chaining method on rigid obstacles before adding deformable terrain.
